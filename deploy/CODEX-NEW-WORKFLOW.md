# Codex 新创作流程检查与修复

验收范围：新建项目、新建 Codex 对话。按用户要求，不迁移或修复旧项目、旧对话和旧草稿。

## 已落实的行为

- 按 drama、narration、ad 和 storyboard、reference_video 装配创作指导。把依赖 Claude 子智能体的创作步骤映射到实际存在的业务工具，不让 Codex 调用不存在的 Skill、Task 或 shell。
- 明确生成、编辑、晋升、内容确认、视觉生成的前置条件。任务排队与最终生成成功分开；沿用用户已有授权，局部修改不扩大为全项目重生成。
- 草稿 revision 和 formal_revision 作为不同的不透明令牌原样传递。正式指纹兼容严格的 `sha256-v1:<64位小写hex>` 等价写法；错误前缀、不同摘要、真实并发修改仍被拒绝，晋升前继续验证正式文件基线。
- 分镜生成要求与发声准入保持一致：真实旁白和角色台词按原顺序分镜，动作及屏幕字不自动成为口播，保留实际台词、说话人、来源与剧情含义。
- 生成回执区分“草稿已保存”和“可以进入确认”；内容确认检查全部分镜的实际发声及重规划标记，一次返回所有阻塞项。Agent 和 HTTP 接口都保留分镜、字段位置、原因及后续动作。
- 经正常编辑与晋升重新校验并清除已解决的标记，不直接删除 `needs_replan` 绕过检查。指导 Agent 针对同一问题最多进行一次局部修复重试，仍失败则说明剩余问题。
- Codex 工具层返回具体参数校验字段；同一调用 ID 重复到达时不重复执行写入，不同参数复用 ID 或过期轮次调用会被拒绝。不同调用 ID 仍由业务层负责并发保护和生成任务去重。
- 增加绑定当前项目/用户的记忆列表、读取和保存工具，复用现有存储及文件限制。启动仅读取有界的记忆索引，按需读取正文。

新会话注册 41 个业务工具（原有 38 个及 3 个记忆工具）和 1 个问答工具。实际 SDK 启动检查通过，共 42 个工具定义；验证没有调用 `turn/start`。

官方协议参考：[Codex App Server](https://learn.chatgpt.com/docs/app-server)。新流程显式传入工作流指令和动态工具，不依赖自动加载 Claude 项目文档。

本轮没有发起真实模型生成，也没有实际调用图片、视频或音频供应商；真实模型创作结果尚未做整集验收。

## 使用范围

刷新页面，创建新的项目和新的 Agent 对话使用修复流程。部署保留当前设置 `gpt-5.5 / xhigh`，没有自动调整模型、推理强度或清理用户数据。

文本、图片仍使用各自设置的生成供应商，视频、音频需要独立可用的供应商。Codex 接入不会自动补足这些服务。Web 导出、调用端点配置等入口继续可用；未提供业务工具的 MP4/BGM 合成及端点适配脚本，不声称已经成为 Codex 自动执行能力。
