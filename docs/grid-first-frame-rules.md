# 多宫格首帧规划与切分规则

## 几何与帧数

- 项目视频比例 `a:b` 是每张首帧的目标比例。保留精确比例，`4:3` 不替换成 `16:9`。
- `r` 行、`c` 列的无间隙联合图比例为 `(c*a):(r*b)`，约分后下发。所有单格大小一致、按行优先映射分镜，每格只表现一个静止首帧。
- 按剧本分段保留分镜顺序；单张上限沿用普通档 9 格、4K 档 25 格。这是容量限制，不是必须使用 3×3 或 5×5。
- 在至多 5 行、5 列和画布比例 1:3 至 3:1 的候选中，优先减少占位，再选择更接近正方形的画布。横竖互换时布局相应转置。无法满足约束时明确拒绝，不丢失分镜或偷偷改变单格比例。
- 超过上限按顺序拆批，末批重新选布局；占位格不生成视频。预览、生成、Agent 与估价消费同一后端规划函数；页面显示分镜数、图片批数及每张图的行列和占位数。
- 例如 12 张 9:16 首帧在容量允许时为 3 行 4 列，联合图 3:4；12 张 16:9 首帧对应 4 行 3 列，联合图 4:3。普通档则拆批，不显示成一张“12 格 · 3×3”。

## 生成与验收

- 提示词明确画格数、行列数、单格和整图比例，无边框、分割线、留白、合并格或格内拼图。每格描述对应分镜的静态首帧，不把两个分镜的动作过渡写进同一格。
- 模型输出不具备像素级布局保证。当前 Codex 图片入口主要通过提示词传达尺寸，不能把“2K/4K”当成已获得相应像素或清晰度的证明。
- 对实际返回图片检查整体比例、分镜映射和明显分割线。强证据表明错行、错列或分割线残留时禁止落格。自动检查不承担人物、构图和隐蔽拼图的语义验收。
- 落格前展示真实裁切缩略图，用户确认每张首帧内容独立、完整。确认绑定图片字节、格子布局、分镜映射和项目比例；内容改变即需重新预览。HTTP 和 Agent 共用落格服务，不允许 Agent 绕过确认自动覆盖分镜。
- 合格图按等分坐标切割，像素余数分配到边界；仅做整数比例所需的最小裁边，不统一删除 2% 边缘。输出保持精确比例、统一像素规格（最长边至多 1024，9:16 为 576×1024，16:9 为 1024×576）。这属于视频输入规格，不等于最终视频分辨率。
- 预览显示原始单格和输出像素。低像素原图放大不会增加细节，应减少每批格数或重新生成更高分辨率联合图；不能用尺寸归一化冒充画质提升。
- 不合格时保留原始联合图与历史版本，重新生成该批或用单张首帧替代。代码修复不自动覆写已有项目图片。
- 已经由旧切分流程产出的首帧在视频准入与执行时检查当前版本的验收记录；没有记录时要求先预览确认并重新落格。单独重生成或上传的首帧按其当前版本来源处理，不受脚本里残留的旧宫格 ID 误拦截。

## 验证范围

覆盖横屏、竖屏、方形及非 16:9 比例，不同帧数、占位和拆批，非整除画布、错误比例、明显分割线、过期确认和落格事务回滚。自动化测试不替代真实模型的出图验收；真实出图应由用户在预览中检查后再进入视频生成。
